人工智能 agent 技术学习笔记

典型Harness架构

  1. 内置的 Planning Tool：Agent 默认拥有规划能力
  2. Compaction 机制：当上下文窗口不够用时，自动进行压缩和摘要
  3. File System 工具：让 Agent 能够与文件系统交互
  4. Starter Prompts：预设的高质量提示词模板
  5. Memory 系统：跨会话的记忆能力
  6. Sub-agents 机制：子任务的自动分发和协调

沙箱

每个人物运行在一个隔离的沙箱环境中，拥有完整的文件系统和Bash执行能力，且会话之间零污染

子智能体

随时可以拆分任务将其委派给Sub-agent并行执行

上下文工程

agent跑长任务最大的挑战是上下文窗口不足而不是agent能力不够

  • 多层Middleware链
  • 上下文摘要
  • 子agent上下文隔离
  • 文件系统作为外部存储（类似内存和磁盘）

长期记忆

分为以下三模块：

  • 用户画像：工作背景、个人偏好、当前关注点
  • 时间线：近期互动摘要、历史背景、长期积累
  • 事实库：具体知识点，存在置信度和分类 记忆更新采用异步队列+去重+防抖设计

早期多agent协作缺陷

  1. 角色固化，agent职责写死，额外添加新agent需要改框架
  2. 上下文浪费，所有agent共享同一份state，部分信息只有少数agent需要知晓，占用了其他agent的上下文
  3. 扩展性差，框架选型太死，导致功能扩展需要大幅度改动

2.0的一些优化方案

从固定的multi-agent图到单一lead agent + middleware chain + dynamic sub-agent

lead agent

2.0将框架设计为集中在一个agent的工具集和中间件链上，这种设计下扩展能力仅需要增加skill或tool

middleware chain

精心编排的middleware链条在agent调用前后进行上下文管理、状态同步、资源分配、线程监控等

sub-agent

通过多线程池架构可将复杂任务委派给sub-agent

threadstate

使用完整的state传递全局信息，而不是只有messages的简单字典

提示词注入

传统做法为全量注入，DeerFlow为只注入skill元信息

提示词生成

使用固定边界符号组成模版

Agent Loop：Skill执行的核心机制

  • before_agent通过中间件创建线程和沙箱
  • before_model通过中间件将图片输入解析
  • 分析请求，匹配skill，决定tool call
  • after_mode通过中间件处理澄清请求以及进行任务追踪
  • Tool_node执行
  • loop工程
  • after_agent通过中间件释放沙盒并进行入队记忆更新

循环退出条件

  • LLM无tool_call正常结束任务
  • LLm调用ask_clarification引发中断
  • 达到recurication报错退出
  • LoopDetection检测到死循环强制退出

性能优化要点

  • 延迟加载MCP（通过搜索按需获取）和skill（披露）
  • ContextVar隔离请求级别的数据
  • 线程锁保护全局缓存
  • 后台线程一步刷新，不阻塞主线程
  • 在配置禁用不常用的Skill
