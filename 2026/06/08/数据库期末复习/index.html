发表时间：2026-06-08

计算机基础 数据库

一、基础概念

1.核心定义与关系

  • DB：长期存储在计算机内、有组织、可共享的数据集合
  • DBMS功能：数据定义、数据操纵、数据库建立与维护，不包含操作系统内核管理
  • DBS：包含DB、DBMS、应用系统、数据库管理员（DBA）

2.数据独立性与三级模式

  • 数据独立性
    • 物理独立性：存储结构、设备变化不影响逻辑结构和应用程序
    • 逻辑独立性：逻辑结构变化不影响应用程序
  • 三级模式：外模式（用户视图，可多个），模式（全局逻辑结构），内模式（物理存储结构）
  • 两级映像：
    • 外模式-模式映像：保证逻辑独立性
    • 模式-内模式映像：保证物理独立性

3.数据模型

  • 三要素：数据结构、数据操纵、完整性约束
  • 概念模型：实体-联系（E-R）模型，区分实体的依据是属性，唯一标识实体的属性为码
  • 常用数据模型：层次模型、网状模型、关系模型

4.数据管理发展阶段

人工管理 -> 文件系统 -> 数据库系统

二、SQL语言特性

1.SQL语言特性

  • 核心功能：数据定义DDL、数据查询DQL、数据操纵DML、数据控制DCL
  • 关键特性：非过程化、不区分大小写、支持嵌入式和独立使用

2.数据定义DDl

  • 数据库创建、表创建、索引创建/删除、视图创建

3.数据操纵DML

  • 插入、删除、更新数据

4.数据查询DQL

  • 基础查询：select、distinct、where
  • 复杂查询：多表连接、嵌套查询、分组查询（group by + having）、居合函数（avg、count）

5.数据控制DCL

  • 权限管理：grant授予、deny拒绝、revoke收回
  • 用户与角色：创建用户、创建角色、角色关联用户

关系规范化理论

1.函数依赖

  • 部分函数依赖：非主属性依赖于部分主键字段确定
  • 完全函数依赖：非主属性依赖于全部主键字段才能确定
  • 传递依赖：非主属性通过中间属性依赖于主键

2.范式NF

  • 1NF：数据项不可分割（原子性）
  • 2NF：1NF + 表中所有非主属性必须完全函数依赖于主属性
  • 3NF：2NF + 表中所有非主属性必须函数依赖于主属性，不存在传递函数依赖
  • BCNF：3NF + 表中所有主属性之间不存在任何种类依赖，主键和候选键都是只依托自己唯一确定的

3.关键术语

  • 候选码：可唯一标识元组的属性
  • 主码：选中的候选码
  • 外码：引用其他表主码的属性

四、T-SQL编程与高级特性

1.变量与批处理

  • 变量声明：declare@变量名 类型
  • 批处理：GO标识结束，批处理发生错误不影响后续执行 2.存储过程
  • 预先编译的T-SQl语句集合，支持输入/输出参数，通过EXEC调用

3.自定义函数

  • 标量值函数：返回单个值
  • 表值函数：返回表对象，调用需加db.前缀

4.触发器

  • 响应表的insert/update/delete操作，包括inserted（新增/修改后数据）/deleted（删除/修改前数据）

5.游标

  • 将集合操作转为单条记录处理，流程：声明->打开->遍历->关闭->释放

五、事务管理与并发控制

1.事务ACID特性

  • 原子性Atomicity：操作要么全做，要么全不做
  • 一致性Consistency：事务执行后数据状态一致
  • 隔离性Isolation：事务执行不受其他事务干扰
  • 持久性Durability：事务提交后数据修改永久有效

2. 并发问题与控制

  • 并发：脏读（读取了另一个事务修改但未提交的数据，如果另一个事务触发了回滚读取到的数据是无效的）、不可重复读（同一个事务内两次读取同一个数据，因为中间有其他事务进行了更改，导致两次读取结果不同）、丢失修改（两个事务同时修改相同数据，最终存储的值只反映了其中一个的更改，忽略了其他修改）、幻读（同一事务内两次执行相同范围查询，因为中间有其他事务执行了插入或删除并提交，导致结果不同）
  • 封锁机制：共享锁（S锁，可读不可写）、排他锁（X锁，可读写）
  • 死锁：多个事务相互等待

3.数据库恢复

  • 核心技术：转储（完整、差异、日志备份）、日志文件（先于操作记录）

数据库

数据库四个基本概念

  • 数据
    • 数据是描述事物的符号记录
    • 数据是信息的载体，信息是数据的内涵
  • 数据库
    • 按照一定结构组织并长期存储在计算机内，可共享的大量数据的集合
    • 永久存储、有组织、可共享
  • 数据库管理系统
    • 用户与操作系统之间的一层应用软件，数据库的核心
    • 包括数据定义功能/操纵功能/库的运行管理/建立与维护功能/库控制语言
  • 数据库系统
    • DBS=计算机系统+DBMS+DB
    • 特点：
      • 数据结构化
      • 数据的共享性，冗余度低且与扩充
      • 数据独立性高

数据管理技术的发展

  • 人工阶段
    • 数据不能共享，冗余度极大
    • 数据无结构
    • 独立性差
  • 文件系统阶段
    • 共享性差，冗余度大
    • 物理独立性好，逻辑独立性差
    • 记录内有结构，整体无结构
  • 数据库系统阶段
    • 共享性高，冗余度低
    • 独立性高
    • 整体结构化

数据库系统结构

三级结构模式

  • 外模式
    • 一个数据库就可以有多个外模式
    • 每个用户至少有一个外模式
    • 外模式通常是模式的子集
  • 模式
    • 一个数据库只有一个模式
    • 概念数据库是物理数据库的逻辑抽象形式
  • 内模式
    • 数据物理结构和存储方式的描述
    • 一个数据库只有一个内模式
    • 内模式对用户透明
    • 物理数据库是概念数据库的具体实现

二级映像

  • 外模式/模式映像
    • 保障逻辑独立性
    • 模式描述全局逻辑结构
    • 外模式描述局部逻辑结构
  • 内模式模式映像
    • 描述全局逻辑结构和存储结构的对应关系
    • 保障物理独立性
  • 内模式/模式映像是唯一的
  • 外模式/模式映像不唯一

优点

  • 保证数据独立性
  • 方便用户使用，简化用户操作
  • 保证数据库安全性
  • 有利于数据的共享

数据模型

  • 数据库系统的核心和基础

数据模型三要素

  1. 数据结构：对数据系统的静态特性的描述
  2. 数据操作：对数据库系统的动态特性的描述
  3. 数据完整性约束条件

分类

  1. 概念模型
    • 实体-联系模型（E-R模型）
  2. 逻辑模型
    • 层次模型
      • 树型结构
        • 节点之间的联系：一对多
        • 有且只有一个根节点没有双亲节点
        • 根以外的其他节点有且只有一个双亲节点
      • 优点：
        • 数据结构较简单，查询效率高
        • 提供良好的完整性支持
        • 缺点：不易表示多对多联系
        • 数据操作限制多，独立性差
    • 网状模型
      • 有向图结构
        • 允许一个以上的节点无双亲
        • 一个节点可以有多于一个的双亲
      • 优点：
        • 较为直接的描述显示世界
        • 存取效力高
      • 缺点：
        • 结构较复杂，不易使用
        • 数据独立性差
      • 网状和层次都是格式化数据模型
  3. 关系模型
    • 二维表结构
      • 关系模型的组成：关系数据结构，关系操作和关系完整性约束条件
    • 优点：
      • 概念单一
      • 建立在严格的数学概念基础上
      • 存取路径对用户透明
    • 缺点：
      • 查询效率不如格式化数据模型
      • 为了提高性能必须进行查询请求优化，增加了开发难度
    • 划分原则：
      • 数据之间的联系方式
    • 面相对象模型
  4. 物理模型

关系数据结构

基本术语

  1. 元组/行/记录
    • 也称记录，关系表中的每一行对应一个元组
    • 一列称为属性/列/字段
    • 其中一个组成元素的具体属性值称为分量
    • 属性的取值范围称为域
  2. 候选码
    • 某个属性或属性组可以唯一标识一个元组
  3. 主码
    • 唯一标识关系中的每行
    • 作为关联表的外键，连接两个表
  4. 全码
    • 所有属性都是这个关系的候选码

关系类型

1.基本关系

实际存在的表

2.查询表

查询结果对应的临时表

3.视图表

由其他表或其他视图导出的表

4.关系操作

  • 数据查询
  • 数据维护
  • 数据控制：安全性控制、完整性控制、并发控制、恢复控制

5.关系操作语言

  • 关系代数语言
  • 关系演算语言
  • 结构化查询语言

6.关系完整性

  • 实体完整性
    • 表中每一行数据都是唯一且可识别的，主键不能重复，不能取空NULL
  • 参照完整性
    • 外键的值只能是参照表中已经存在的主键或空NULL，防止孤儿记录
  • 用户自定义完整性
    • unique
    • not null
    • default
    • check

7.关系代数

  • 基本运算
    • 并U：合并去重
    • 差-：去重
    • 笛卡尔积*：以关联字段进行复制拼接
    • 选择：、投影
  • 传统集合运算
    • 并、交、差、笛卡尔积
  • 专门的关系运算
    • 选择：select满足条件的行
    • 投影：从表中提取指定列并去重
    • 连接：根据指定字段组合列出所有的元组
    • 除：笛卡尔积逆运算，找到除数表（S）与被除数表（R）中重合的字段。对于不重合字段（X）中的每一个具体取值，去被除数表（R）中找出它对应的所有重合字段组合（即象集）。如果这个象集完全包含了**除数表（S）**中重合字段的所有组合，那么除运算的结果就保留这个不重合字段的取值。B站讲解视频
  • E-R图转换为关系模式时，实体和联系都可以表示为属性

数据库保护

1.安全性控制

  • 保护数据库，防止不合法的使用造成的数据泄露和破坏
  • grant授权，revoke回收权利
  • 常用方法
    • 存取控制
      • 包括定义用户权限和合法权限检查
      • 自主存取控制方法
        • 通过grant和revoke实现
        • 用户权限分为数据库对象和操作类型两部分
      • 强制存取控制方法
        • 系统规定只有某一许可证级别的用户才能存取某一个密级的数据对象
        • 数据库管理系统管理的所有实体分为主体和客体
    • 视图机制
    • 审计：数据库安全审计系统提供了一种事后检查的安全机制
    • 数据加密：根据一定的算法将原始数据转变成不可直接识别的格式，包括存储加密和传输加密两种
  • 完整性控制：数据库中数据的有效性、正确性、相容性
  • 并发控制
  • 恢复

访问控制机制

1.事务

  • 用户定义的一个逻辑一致的数据库操作序列，这些操作要么全做，要么全部做，是一个不可分割的工作单位（类似超级步，但是没有恢复）
  • 事务是恢复和并发控制的基本单位
  • 多个事务的执行次序叫调度

2.特性

  • 一致性：保持数据库从一个一致性状态到另一个一致性状态
  • 原子性：事务是数据库的逻辑工作单位
  • 隔离性：一个事务的执行不能被其他事务干扰，事务内部操作的数据与外界是隔离的
  • 持续性/永久性：事务一旦提交，对数据库中数据的改变就该是永久性的 3.定义事务
  • begin/start transaction开始
  • commit提交事务，正常结束
  • rollback事务回滚
  • undo撤销事务

数据库恢复

概念

将数据库从错误状态恢复到某一已知的正确状态

故障的种类

  • 事物内部故障
  • 系统故障
  • 介质故障
  • 计算机病毒

故障可能产生的破坏

  • 数据库本身被破坏
  • 数据库没有被破坏，但数据库不正常

常用恢复方式

  • 数据转储
  • 等级日志文件

并发控制

概念

确保及时纠正由并发操作导致的错误的一种机制

常用技术

封锁、时间戳、乐观锁、多版本并发控制

封锁

两种锁类型：

  • 排它锁：X锁，别的事务对加锁对象不能进行任何类型的操作
  • 共享锁：S锁，对事务可读但不能写，其他事务只能再次对该事务加S锁，但不能加X锁 封锁协议：
  • 一级封锁协议：事务在修改数据前必须加X锁，直到事务结束才释放
  • 二级封锁协议：事务在读取数据前必须加S锁
  • 三级封锁协议：在二级的基础上，只有事务结束才释放
