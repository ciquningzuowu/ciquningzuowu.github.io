APScheduler 库笔记

基本概念

APScheduler 是 Python 的定时任务调度框架，可以按照指定日期、固定时间间隔或 Cron 表达式触发任务。它不仅支持添加、删除和修改任务，也可以将任务持久化到数据库中，避免程序重启后任务丢失。

核心组件

组件 作用
trigger 触发器，决定任务何时执行。
job store 作业存储，负责保存任务定义。
executor 执行器，负责在线程池或进程池中执行任务。
scheduler 调度器，连接触发器、作业存储和执行器，提供统一操作入口。

调度器类型

调度器 适用场景
BlockingScheduler 在当前线程运行，会阻塞主线程。
BackgroundScheduler 在后台线程运行，不阻塞主线程。
AsyncIOScheduler 适合 asyncio 异步应用。
GeventScheduler 适合 gevent 应用。
TornadoScheduler 适合 Tornado 应用。
TwistedScheduler 适合 Twisted 应用。
QtScheduler 适合 Qt 桌面应用。

作业存储

存储方式 特点
MemoryJobStore 默认内存存储，程序重启后任务丢失。
SQLAlchemyJobStore 持久化到关系型数据库。
MongoDBJobStore 持久化到 MongoDB。
RedisJobStore 持久化到 Redis，适合需要快速读写的场景。

触发器类型

触发器 说明
date 在指定时间执行一次。
interval 按固定时间间隔重复执行。
cron 按 Cron 表达式周期执行。

使用注意事项

  • 对长期任务建议使用持久化 job store，避免程序重启后任务丢失。
  • CPU 密集型任务优先考虑进程池，I/O 密集型任务通常使用线程池即可。
  • 在异步项目中应选择 AsyncIOScheduler，避免阻塞事件循环。
  • 分布式部署时需要额外设计任务锁或单实例调度策略，避免多实例重复执行同一任务。
