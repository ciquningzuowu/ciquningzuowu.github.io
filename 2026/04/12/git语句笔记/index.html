学习笔记 计算机基础 实用工具

一些基础内容

  • git是分布式的，下载的代码是在本地备份的，每个管理员都是独立的备份，没有绝对的“主服务器”
  • git存储内容是按元数据存储的

1.基础工作流程

Git的工作流程分为四个主要部分：

  1. 工作区：实际修改文件的地方（例：pycharm工作目录）
  2. 暂存区：觉得修改的差不多后使用git add传入暂存区准备提交（项目根目录下的隐藏文件）
  3. 本地仓库：使用git commit将暂存区内容进行传入本地仓库进行修改（计算机本地文件）
  4. 远程仓库：使用git push将本地仓库内容更改同步到远程仓库（例：github）

基础命令：

  1. 克隆仓库：git clone https://github.com/username/repo.git，克隆的仓库会以仓库名为文件名保存在当前目录下
  2. 创建新分支：git checkout -b new-feature，使用git switch -c new-feature可切换当前项目的提交链接的分支（分支本质是指针，Switch则是更改指向哪个项目的暂存区）
  3. 暂存文件：git add filename 或 git add .（添加某个文件或所有修改的文件）
  4. 提交更改：git commit -m "Add new features"。将暂存区的更改提交到本地仓库
  5. 从远程仓库拉取最新更改到本地仓库：git pull origin main 或 git pull origin new-feature。推送本地更改前，最好先从远程仓库拉取最新的更改，以免冲突（远程仓库和本地仓库都对同一个部分进行了更改）
  6. 推送更改：git push origin new-feature,将本地提交推送到远程仓库
  7. 创建Pull Request：git push -u origin feature-login
  8. 合并更改：使用git merge对本地分支进行合并和更改，将制定分支的更改合并到当前分支
  9. 删除分支：git branch -d new-feature,git push origin --delete new-feature，删除分支或从远程仓库删除分支。

2.创建仓库

进入准备建库的目录地址，使用git init初始化仓库，该命令会在目录下生成一个.git目录，包含了资源的所有元数据。也可使用指定目录作为git仓库，只需要在init 后添加目录名参数。

1.使用git add后git commit -m "提交描述"可将文件纳入版本控制

2.使用git clone <repo> <dcirectory>可以将指定仓库的项目克隆到指定目录下（不带目录参数时默认当前目录）

3.使用git config可以显示当前的git配置信息。git config -e 可以编辑git配置(-e 后面添加--local/global/system可以针对本地/当前用户全局/整个系统上所有仓库，三者优先级由左往右)

4.分支管理

git的分支实际是指向更改快照的指针，每个分支都是独立的开发线路，可以在不影响主线的同时继续工作。

  1. 使用git checkout -b branchame可以创建新分支并切换到该分支，直接用git checkout branchname可以直接切换分支。切换分支时git会用该分支最后提交的快照替换工作目录的内容，所以多个分支不需要多个目录

  2. 使用git branch查看分支添加-a和-r可以分别查看远程分支与本地远程所有分支。

  3. 使用git merge branchname可以合并分支

5.日志管理

  1. 使用git执行了若干操作后可通过git log [选项] [分支名/提交哈希]命令查看日志，常用选项如下，第二个参数则是配合第一个参数，如--since后加时间

常用选项：

  • -p：显示提交的补丁（具体更改内容）。
  • --oneline：以简洁的一行格式显示提交信息。
  • --graph：以图形化方式显示分支和合并历史。
  • --decorate：显示分支和标签指向的提交。
  • --author=<作者>：只显示特定作者的提交。
  • --since=<时间>：只显示指定时间之后的提交。
  • --until=<时间>：只显示指定时间之前的提交。
  • --grep=<模式>：只显示包含指定模式的提交消息。
  • --no-merges：不显示合并提交。
  • --stat：显示简略统计信息，包括修改的文件和行数。
  • --abbrev-commit：使用短提交哈希值。
  • --pretty=<格式>：使用自定义的提交信息显示格式。
  1. 使用 git blame [选项] [文件路径]可以显示指定文件的每一行代码是由谁在什么时候引入或修改的。

常用的选项包括：

  • -L <起始行号>,<结束行号>：只显示指定行号范围内的代码注释。
  • -C：对于重命名或拷贝的代码行，也进行代码行溯源。
  • -M：对于移动的代码行，也进行代码行溯源。
  • -C -C 或 -M -M：对于较多改动的代码行，进行更进一步的溯源。
  • --show-stats：显示包含每个作者的行数统计信息。
  1. 使用部分命令可进行恢复和回退：
  • git chekout：切换分支或恢复文件到指定提交
  • git reset：重置当前分支到制定提交（软重置、混合重置、硬重置）
  • git revert：创建一个新的提交以撤销制定提交，不改变提交历史
  • git reflog：查看历史操作记录，找回丢失的提交

6.git标签

概述：给代码仓库某个时刻拍一张快照，并进行标识。git的每次提交都有一个哈希值对应，标签的作用为添加一个额外引用，如v1.0.1，使得后期能够快速定位这次提交时的代码状态

轻量标签：

  1. 使用git tag (-a) tagname (hand_log_hash)可以添加标签（未添加标签的提交可以追加hand_log_hash参数选择为哪次提交追加注解,使用git log --decorate可以查看。)
  2. 使用git push repo时可以添加第四个tagname参数，作用为推送某条tag，直接添加--tags会推送所有标签
  3. 使用git tag -d tagname可以删除某条标签git push origin --delete tagname 可以远程删除

附注标签（存储了创建者的名字、电子邮件、日期以及包含的标签信息）:

  1. 使用git tag tagname -m message 时添加-a会打开一个编辑器，让你像提交一样给这次标签添加注解，可以记录标注时间与标注用户）
  2. 使用git show tagname可以查看指定标签的素有相关信息，直接使用git tag则会展示所有标签名称

7.Git Flow

概述：一套经典广泛的Git分支管理策略。

五种核心架构分支：

  1. master/main： 存放绝对稳定的、随时可以发布的代码。严禁提交代码到这里 只能通过其他分支合并进来，每次合并通常代表一次版本发布
  2. develop：日常开发的主线，所有的功能开发完成后的都会合并到这里。包含了最新的代码，但不一定经过充分测试。
  3. feature：从develop分支创建，用来开发具体的新功能，开发完后会合并回develop分支
  4. release：当develop上的功能积累到一定程度，准备发布新版本时创建，用于进行最后的测试、修复小Bug，更新版本号，此时不再开发新功能。发布完成后，同时合并到master上线和develop并打上版本标签
  5. hotfix：从master创建，当生产环境出现紧急Bu时，创建此分支进行修复。当修复完成后，合并到master上线以及develop

8.进阶操作

  • 交互式暂存：逐块选择要暂存的更逐块选择要暂存的更改
  • Git Stash：临时保存工作进度，方便切换任务
  • Gir Rebase：将一个分支上的更改移动到了另一个分支上，保持提交历史线性
  • Git Cherry-Pick：选择特定提交并应用到当前分支

（1）交互式暂存

概述：git add可以选择性地将文件或文件的一部分添加到暂存区。使用git add -p后，Git会逐块显示文件的更改，可以选择是否暂存每个块，常用选项包括：

  • y：暂存
  • n：跳过
  • s：拆分
  • e：手动编
  • q：退出暂存

（2）Git Stash

概述：git stash命令允许你临时保存当前工作目录的更改,以便切换到其他分支或处理其他任务（该功能基于git的一项规则：当当前分支存在未提交的更改时不允许切换分支）下为一些分支命令：

  • git stash list：查看存储的进度
  • git stash apply：应用最近一次存储的进度
  • git stash pop：应用并删除最近一次存储的进度
  • git stash drop stash@{n}：删除特定存储
  • git stash clear ：清空所有存储

（3）Git Rebase

概述：使用git rebase branchname可以将代码基石变换，例如你是从第一版为基础开始更改的，同事改出了后续版本，你可以使用该功能将基石变为后续版本，但这样做很容易发生冲突，需要严格的人工介入，使用git rebase -i commit可进行交互式变基（处理你对源项目的每次提交），允许过程中变基、删除、合并和提交，对前述问题有所改善。下为衍生命令：

  • pick；保留提交
  • reword：修改提交
  • edit：编辑提交
  • squash：将当前提交与前一个提交合并
  • fixup：将当前提交与前一个提交合并，不保留提交信息
  • drop：删除提交

（4）Git Chery-Pick

概述：使用git chery-pick commit可以选择特定的提交应用到当前分支。

9.Github

  2. 使用git fetch从远程仓库拉取新分支和数据
